### Lockstep-starvation verdict

The original pattern still exists below the new batch boundary:

- Per-domain planning is one `gather`; document generation is another `gather`; each document queues a draft and then a rewrite through the same fair semaphore. No disk artifact is emitted by either stage. Concrete tests to add:

1. Run corpus generation as a subprocess against a slow local OpenAI-compatible server; SIGKILL during batch 2 and assert batch 1 survives, batch 2 is absent/ignored, and restart sends no requests belonging to batch 1.
2. Kill during planning, draft and rewrite separately. After per-response persistence is added, assert restart sends only missing request hashes.
3. SIGKILL during a deliberately large cache append; assert startup loads all complete records and quarantines only the torn tail.
4. Kill purity/eval judging after N verdicts; restart must send exactly `total-N` requests and preserve raw verdicts.
5. Kill sampling during a JSONL write and between grid primary/logprob writes; neither state may satisfy completion validation.
6. Terminate a pod after one arm has completed; delete its local `/workspace`; a fresh pod must restore that arm remotely and start at the next one.
7. Kill training after epoch 1 and after an arm upload; verify epoch resume for the former and HF skip for the latter.
8. Add fingerprint-negative tests: alter model, domains, seed, prompt version, checkpoint or sampling parameters and assert stale artifacts are rejected rather than reused.

## 2. Verified solid

These specific invariants are genuinely present:

- For an unchanged configuration, each completed synthdoc batch is file-fsynced and atomically renamed; malformed JSON batches are rejected and regenerated. A parent-directory fsync is still absent, so this is strong for SIGKILL/network failure but not a full sudden-power-loss guarantee. [`gen/__init__.py:174`](src/scimt/gen/__init__.py:174), [`gen/__init__.py:369`](src/scimt/gen/__init__.py:369)
