## 0. PRIORITY ANSWER -- was the GLM 81,920-row AFT scale-up (#1b) trained on MIXED-TEMPLATE data?

**Yes.** The #1b data was built by the same template_diversity_v1 machinery as the 8,192-row campaign/grid: every training row (agreement and conflict) is rendered with one of the **90 training templates**, the ~10 held-out templates are evaluation-only, and every GLM endpoint was evaluated on all three surfaces (canonical / trained-template / held-out-template). Evidence:

1. Builder imports the template module and the campaign's schedule: `HP/DFV/aft_size_mixture_v1/build.py:26-40` (`sys.path` adds `template_diversity_v1`; `import templates`; `from ... import build_aft_mixtures as old`; `check_prompt` from `build_template_diversity_v1`).
2. Template schedule over the 81,920 rows from the training templates only: `build.py:121-123` -- `tids = [t.template_id for t in templates.training_templates()]`, `schedule = old.template_schedule(tids, ROWS)`. `old.template_schedule` is the balanced deterministic assignment seeded `TEMPLATE_SCHEDULE_SEED = 20_260_831` (`HP/DFV/build_aft_mixtures.py:73-75, 171-182`).

Coin/charter rows share the prompt (same template) and differ only in the answer (`build.py:155-157`).

### 1.2 Mixture construction and nesting

### 1.4 How a cell is evaluated

- Two endpoints per cell, `aft-step256` and `aft-step512`, served from ONE resident base with LoRA adapters by `experiments/prior_coins/generalization_forensics/pod/pod_generate_multi.py`, run under a separate vLLM venv `/workspace/venv-dispatch-eval/bin/python` (`gemma_grid_run.py:119-131`; `pod/evaluate.py:50-54, 241-258`). GLM (`MODEL_FAMILY == "glm45_air"`) evaluates step 512 only in the campaign runner (`contracts.py:850-864`) but the 81,920-row scale-up evaluated both epoch boundaries (2,560 / 5,120).
- Prompt sets: 18 = 6 slices x 3 surfaces, from HF dataset `sidbaines/scimt-prior-coins-dispatch-sdf-aft-v1-data` @ `53007a79779078f8dfc1902758afbcd33837e4c7`, prefix `extensions/template_diversity_v1/data/prompts/<slice>__<surface>.jsonl` (`contracts.py:210-212, 877-883`; `evaluate.py:95-114`). Slices: `eval_trained_agreement`, `eval_trained_conflict`, `eval_holdout_agreement`, `eval_holdout_conflict`, `eval_trained_adjacent`, `eval_holdout_adjacent`; surfaces `canonical`, `trained` (templates seen in AFT), `heldout` (unseen templates). "trained/holdout" = the 5 trained vs 2 held-out target clauses; the canonical heat maps read the **held-out template x trained clause** split (`results_grid/README.md:257-261, 575-576, 679`).
- Prompt counts (from `scored/gemma3_12b_19m/charter/eval.json` `n`): trained_agreement 2,000; trained_conflict 2,000; trained_adjacent 1,000; holdout_agreement 800; holdout_conflict 800; holdout_adjacent 400 = **7,000 prompts per surface, 21,000 per endpoint** (also `pod/eval_runtime.py:70-71`). - Decoding: one greedy sample per prompt: `SamplingParams(temperature=0.0, n=1, max_tokens=64, seed=42)`, `max_model_len 4096`, `gpu_memory_utilization 0.84`, `enforce_eager` (default; CUDA graphs opt-in), `enable_lora=True`, `max_lora_rank` from runtime (`pod_generate_multi.py:123-135`; `eval_runtime.py:78-104`). - Eval-completeness gate: every response file validated against the prompt ids (`validate_responses`, :92-99); both epochs must score or the cell fails (:243-247).
